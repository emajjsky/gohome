# GoHome 三端控制面矩阵

更新时间：2026-08-07

这份矩阵是生产边界的单一依据。盒子管理端、正式 iOS App 和生产云不得因为历史兼容代码而共同拥有同一项业务职责。

## 所有权规则

| 能力 | 正式调用方 | 唯一业务所有者 | 盒子职责 |
| --- | --- | --- | --- |
| 账号、家庭、老人资料、消息、记忆、社区内容 | iOS -> 生产云 | 生产云 | 不提供业务 API |
| 盒子绑定 | iOS -> 盒子局域网 `/pair`，盒子出站到云交换凭证 | 生产云保存绑定关系 | 只验证短时配对窗口并执行一次交换 |
| 摄像头增删、编辑、启停 | iOS -> 生产云 `/api/cameras*` | 生产云保存配置 | 通过设备令牌拉取配置，原位应用并回报状态 |
| 隐私模式 | iOS/管理端 -> 生产云；盒子出站同步 | 生产云保存家庭期望值 | 逐路生成唯一隐私成品帧 |
| 实时视频会话 | iOS/管理端 -> 生产云 | 生产云签发媒体会话，MediaMTX 承载媒体 | 采集、分析、合成、发布 |
| 设备状态与摄像头状态 | 盒子出站 `/api/v1/device/heartbeat`、`/sync` | 生产云保存云端视图 | 只报告真实运行状态，不接受用户侧伪造状态 |
| 事件与活动上行 | 盒子出站 `/api/v1/device/events`、`/activity-intervals` | 生产云去重、验证、通知 | 生成事件证据并使用幂等键上行 |
| APNs 推送、通知去重、回执 | 生产云 | 生产云 | 不直连 APNs、不生成通知 |
| 包发布与 rollout 编排 | 生产云 | 生产云 | 不提供用户侧发布/rollout API |
| 签名校验、原子安装、失败回滚 | 云端命令 -> 盒子 | 盒子本地安全执行器 | 仅接受已鉴权、已签名、已授权的设备命令 |

## 正式局域网入口

正式 iOS 只直接访问以下盒子入口：

| 入口 | 用途 | 允许的边界 |
| --- | --- | --- |
| `GET /api/lan/discovery` | 发现盒子和配对窗口状态 | 无业务数据 |
| `GET /api/cameras/discover` | 局域网摄像头发现 | 只返回扫描结果 |
| `POST /api/lan/config-sync/wake` | 配置变更后唤醒盒子同步 | 仅私网来源 |
| `GET /pair` | 短时安全配对 | 仅窗口开放时交换一次凭证 |

盒子管理端的 `/api/admin/*`、`/api/setup/*`、`/api/cameras/*` 和诊断接口只服务盒子本地管理，不属于云端 App 业务接口。

## 设备出站接口

盒子使用设备令牌出站访问生产云：

| 入口 | 作用 | 结果归属 |
| --- | --- | --- |
| `GET /api/v1/device/config` | 获取摄像头、规则、隐私模式和维护命令 | 盒子应用并回报 |
| `GET/PUT /api/v1/device/video-privacy` | 同步隐私期望值 | 云端保存，盒子执行 |
| `POST /api/v1/device/heartbeat` | 设备心跳 | 云端状态 |
| `POST /api/v1/device/sync` | 设备、摄像头、运行指标和配置回报 | 云端状态 |
| `POST /api/v1/device/activity-intervals` | 活动区间批量上行 | 云端活动记录 |
| `POST /api/v1/device/media-assets/upload` | 事件证据上传 | 云端/COS 资产 |
| `POST /api/v1/device/events` | 事件幂等上行 | 云端事件与通知 |
| `GET /api/v1/device/vision-verifications` | 读取云端多模态验证结果 | 盒子同步验证状态 |
| `GET /api/v1/device/event-log` | 读取设备关联事件状态 | 盒子同步状态 |

## 当前明确的缺口

当前仓库已经具备盒子端签名包校验、原子安装和运行时回滚能力，但 `local-app-server/server.js` 尚未提供对应的生产包发布与 rollout API。因而：

1. 不能把盒子上的用户侧 `package-releases`、`package-executions`、`device-rollouts` 路由误当成正式云端闭环。
2. 在云端发布、命令和回执链路补齐前，不删除签名执行器，也不让管理端显示“可升级”假状态。
3. 设备心跳、设备同步、事件上行不是用户侧控制 API，必须保留并单独验收。

下一步实现包发布和 rollout 的云端所有者后，盒子只保留设备命令消费、签名验证、原子安装和回执，不再保留用户账号或家庭维度的包管理入口。
